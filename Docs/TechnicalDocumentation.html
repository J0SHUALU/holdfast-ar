Holdfast AR: Technical Documentation

Mobile AR survival shooter · Portrait · Unity 6 + AR Foundation (ARCore / ARKit) · Developer: Joshua Chukwuebuka Moses

Story: you are the last colonist on the frontier world Kepler-9. Your landing dome has come down on the only flat ground you can find (the real floor), and the planet's natives, alien grunts and armoured bug mechs, are closing in. Hold the dome with your ray gun until the evac ship arrives (the match timer).

1. Architecture overview

The game is split into small systems that talk through a GameManager (the coordinator) and a static GameEvents hub. Gameplay code never references UI classes: it raises events, and the HUD listens. The match flow is driven by a state machine: MainMenu → Placement → Playing → GameOver, and Restart jumps straight back to Playing.

2. OOP structure

PrincipleWhere it is applied
EncapsulationState lives in private fields with read-only properties: GameSession.Score only changes through RegisterKill(), PlayerHealth.Current only through TakeDamage()/ResetHealth(), and Leaderboard hides its JSON/PlayerPrefs storage behind Add() and Sessions. Inspector values use [SerializeField] private.
AbstractionIDamageable (Team, IsAlive, TakeDamage) lets projectiles and melee attacks hurt anything without knowing concrete types. IPoolable abstracts pool reset hooks. Abstract classes Enemy, GameState and UIPanel define the contract without the details.
InheritanceEnemy → MeleeEnemy, ShooterEnemy share health, chasing, facing, cooldown, hit feedback and death. GameState → 4 states; UIPanel → 5 panels; Singleton<T> → GameManager, AudioManager.
PolymorphismEnemy.Update() calls the abstract StoppingDistance and Attack(): the Brute stops at 0.35 m and swings, while the Sentinel stops at 1.4 m and fires. Both drive the same Animator parameters (Speed, Attack, Hit, Die), so each model plays its own walk, punch or shoot, hit and death clips through one shared code path. The state machine only calls Enter/Tick/Exit, and UIManager only calls Build/Show/Hide/Tick on any panel.

3. Design patterns used and why

PatternClassesWhy
Object PoolObjectPool<T>, ProjectilePool, Projectile : IPoolableBullets are fired many times per second. Creating/destroying them causes GC spikes and frame drops on phones, which is especially bad for AR tracking.
StateGameState, GameStateMachine, 4 concrete statesEach phase owns its setup/teardown (e.g. PlayingState.Exit() wipes enemies and bullets), which avoids a large switch and makes Start → Play → End transitions explicit.
SingletonSingleton<T> → GameManager, AudioManagerExactly one coordinator and one audio owner, reachable from anywhere; duplicates self-destroy.
FactoryEnemyFactoryOnly one class maps EnemyType → prefab and injects dependencies (EnemyContext: target, difficulty, enemy bullet pool). New enemy types need no spawner changes.
ObserverGameEvents, HudPanel, SpawnMarkers, PlayingStateHealth, score, kills, time and enemy spawns are broadcast; SpawnMarkers listens to EnemySpawned to show a pin over each new enemy, or an edge arrow when it is off screen. The HUD subscribes in OnShow and unsubscribes in OnHide, so gameplay stays independent of UI.

4. Object Pool implementation

  • Pre-initialised: ProjectilePool.Awake() creates ObjectPool<Projectile>, which instantiates all objects up front (40 player bullets, 30 enemy bullets), deactivates them and pushes them onto a Stack. This is the only Instantiate for bullets.
  • Get: pops an inactive bullet, sets position/rotation, activates it and calls OnTakenFromPool(). If the pool is empty, the oldest active bullet is recycled (tracked in a LinkedList) instead of allocating, so there is never an Instantiate during gameplay.
  • Release: on hit or after its 3 s lifetime, the bullet calls back to its owner pool: OnReturnedToPool() → deactivate → push. Double releases are ignored.
  • Proper reset: age, speed, damage, direction and team are cleared, and the TrailRenderer is cleared and toggled so no streak is drawn from the previous position. ReleaseAll() runs when a match ends.
  • Hit detection: each frame the bullet sphere-casts along its path (no tunnelling at AR scale) and damages the nearest IDamageable whose Team differs from the shooter's.

5. Sound system structure and sources

AudioManager (Singleton) is the only owner of AudioSources. Enemies and bullets have none, which avoids duplicate components: one 2D source for UI/player sounds (PlayOneShot, so rapid shots overlap on one source), one looping 2D music source, and a fixed round-robin pool of 6 spatial 3D sources (linear roll-off 0.3–6 m, tuned for room-scale AR) that are moved to the enemy's position for positional sounds. Clips load from Resources/Audio by the SoundId enum name, with per-sound volume and a slight random pitch to avoid repetition.

6. AR implementation notes

  • Plane detection: ARPlaneManager.requestedDetectionMode = Horizontal. The default visualiser is replaced by NamedPlaneVisualizer, which triangulates each plane's boundary into its own mesh and maps UVs in metres (0.6 m per tile), so the texture reading JOSHUA CHUKWUEBUKA MOSES tiles across the real floor. It only renders while the plane is Tracking and not subsumed.
  • Tap-to-place: ARRaycastManager.Raycast(PlaneWithinPolygon) → ARAnchorManager.AttachAnchor(plane, pose), and the arena is parented to the anchor. After placement, later taps are ignored, the plane manager is disabled (no new planes) and trackers are hidden.
  • Spawning on planes: at placement, PlaneSpawnArea stores every horizontal plane polygon in arena-local space. Spawns pick random points 0.9–2.2 m from the base and at least 1.1 m from the player, then keep only points inside a real plane polygon.
  • Portrait UI: every panel is built in code inside a 1080×1920 portrait frame fitted to the device safe area, using the Kenney UI Pack (Space Expansion) sprites (9-sliced, tinted to the red space palette) and the Kenney Future font. The FIRE button sits bottom-right, clear of the centred ray gun, and the gun is hidden outside a match.
  • Leaderboard: SessionRecord list serialised with JsonUtility into PlayerPrefs; the newest record is inserted first and the list is trimmed to 5.
